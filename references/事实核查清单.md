# 事实核查清单（工作流第 5 步）

定稿前逐条核对。原则：查得到才写，查不到就改写为间接表述或删除，不编造。

## 直接引语

- 每条引语找到可查证的原文出处（演讲、访谈、官方文档、邮件列表、著作），在素材卡记下出处。
- 只有转述、找不到原文的「名言」：改为间接引语（不加引号），或删除。
- 翻译引语注明系大意，或干脆改写成间接引语。

## 数字与统计

- 每个数字给出来源机构 + 年份 + 统计口径。
- 示例写法：「微软 MSRC 2019 年称，约 70% 的安全漏洞源于内存安全问题」。
- 口径不明的排行榜名次不写精确名次，写「某榜单前列」并附素材链接。

## 人名与时间线

- 创造者姓名、当时所属公司、关键年份逐条核对（示例：Graydon Hoare 2006 年个人项目、2009 年 Mozilla 赞助、2015 年发布 1.0）。
- 轶事（电梯故障、爬楼之类）注明出处；查不到出处的轶事改为「社区流传的说法」或删除。

## 代码

- 示例代码在语言当前稳定版上可运行，描述的输出与实际执行结果一致。
- 语法和 API 不凭印象写，对照官方文档核一遍。

## 社区梗与绰号

- 写明来源社区（论坛、博客、语言官方渠道）与大致时间。
- 「据说」「有人认为」这类无法溯源的说法不进正文。

## 热点事件（热点版）

- 每个热点事件至少一条可查信源（官方公告、当事公司声明、权威媒体报道、CVE 编号），链接记入素材卡；能找到两条独立信源交叉核实更好。
- 「上周」「这几天」落笔前先换算成具体日期再核对；事件发生、修复、回应等关键时间点逐个核。
- 事件仍在调查、原因未定论的：正文只写已证实部分，并注明「截至 X 月 X 日」，推测与传闻不进正文。
- 用户上传的热点素材同样逐条核查——上传不豁免，与信源有出入的以核查结果为准。
