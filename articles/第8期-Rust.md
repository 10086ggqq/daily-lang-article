每天认识一门编程语言第八期——Rust

写在前面

"一件东西若人人都有份，往往就没人真的心疼；一块责任若谁都能沾手，多半最后落在地上。很多混乱，根源不是没人管，而在于主人太多。"

这让我想起 Erlang。
这门为电话交换机而生的语言，从第一天起就认定：程序一定会出错，就像人一定会犯错。
它不追求"永不崩溃"，而是坦然让坏掉的进程死掉，再由一个叫"监督者"的角色把它轻轻拉起。

[推荐配图：雾气中的电话交换机机柜，无数小灯明灭，一盏小灯熄灭，旁边其余灯光照常亮起，冷暖对比]

起初我觉得，这简直是成熟的极致——既然世界注定不完美，那就原谅它。
直到我遇见 Rust，它偏要问一个更"轴"的问题：
如果在程序跑起来之前，就把每一样东西的主人都钉死，有一整类灾祸，是不是压根没机会发生？

开发者简介

Rust 的创造者 Graydon Hoare，2006 年还是 Mozilla 的程序员。
那年他回到温哥华的公寓，电梯又因为软件崩溃停了，他住在二十一楼，只能一层一层爬上去。
爬楼梯时他越想越气："我们这些搞计算机的，连一部不崩溃的电梯都写不出来吗？"

他清楚，这些崩溃多半不是玄学，而是 C 和 C++ 里那块被反复踩错的内存。
微软后来算过，自家代码约七成的安全漏洞，都源于内存错误。
那天晚上他打开电脑，开始写一门新语言，取名 Rust——锈，来自一类极其顽强、"为存活而生"的真菌。

他有句话很能说明脾气："凡是进 Rust 的东西，都得是至少十年前就被验证过的。"
不炫新，不冒进，只把被时间证明过的想法，认认真真打磨成日常能用的工具。
Mozilla 2009 年正式赞助，让它去写实验性浏览器引擎 Servo；1.0 拖到 2015 年才发布，九年磨一剑。

主要内容

Rust 最核心的规矩，是个稍微技术一点的词：所有权（Ownership）。
意思朴素得近乎常识：Rust 里每一块数据，都有且只有一个主人。
主人活着，数据就在；主人走了，数据立刻被收拾干净。
主人也可以把它转手给别人，叫"移动"；或者只是借出去看看、不收走，那叫"借用"。

比如这几行代码，讲的是一口"锅"的交接：

```rust
fn main() {
    let a = String::from("锅");
    let b = a;              // 所有权从 a 移交给 b
    println!("{}", b);
    // println!("{}", a);   // 编译报错：a 已经不管这口锅了
}
```

编译时 Rust 就会拦住你：想再用 a？不行，这口锅已经不是你的了。
它把过去要等运行时才炸、甚至上线后才暴雷的错，提前到敲键盘的阶段就掐灭。

更妙的是多线程。两个人同时改一块数据，历来是并发崩溃的重灾区，而 Rust 用所有权规则，让这种代码在编译期就写不出来——这正是它敢叫"无畏并发"的底气。

[推荐配图：两条并行的河流各自向前，中间隔着一道透明栅栏，河水无法越界相撞，极简扁平风]

这一切还不靠垃圾回收，没有程序突然停下打扫世界的停顿，性能贴着 C 和 C++ 走。

一些论点

当然，代价也是真的。
初学者几乎都要和那个"借用检查器"吵上几架，写惯了别的语言，会觉得处处受限，仿佛代码还没跑，先被审了一遍。
有人嫌它啰嗦、上手陡，这些批评不算冤枉。

可换个角度想，那些让你在编译期难受的规矩，恰恰是替你把深夜的线上事故、把二十一楼的楼梯，提前走了一遍。
Erlang 选择在崩掉之后温柔地重启，Rust 选择在出发之前把责任写清，一个是事后的宽容，一个是事前的清醒，都是成年人应对世界的方式。

但规则也会被神化。若把所有权当成不容通融的教条，事事都要先划清界限，协作也会变得僵硬。
真正的成熟，是知道哪些东西必须主人唯一，哪些时候尽可以放心地借、大胆地交出去。

Rust 打动我的，并不是"快"，而是它对责任的那份诚实——
每一样东西都有人管，每一次交接都清清楚楚，没人能在出事之后耸耸肩说"我以为是别人的"。
混乱往往不是因为没人负责，而是因为人人都以为会有别人负责。
